# Установка нового сервера OpenBioMaps

На этой странице представлен краткий обзор установки сервера и описаны
наиболее важные настройки уровня проекта в `local_vars.php.inc`.

Для большинства установок следует использовать среду на основе Docker. После
установки сервера используйте интерфейс Supervisor для управления
низкоуровневой конфигурацией системы и проекта.

> **Важно:** Приведённые ниже значения являются примерами конфигурации, а не
> полным конфигурационным файлом. Проверяйте каждое значение перед
> использованием. Не добавляйте пароли, секреты клиентов, ключи шифрования и
> другие учётные данные в репозиторий исходного кода.

## Конфигурация уровня проекта

Некоторые низкоуровневые настройки проекта хранятся в
`local_vars.php.inc`. Обычно этот файл обслуживается администратором сервера
через режим Supervisor, относящийся к конкретному проекту.

Настройки, доступные через обычный интерфейс администрирования проекта, как
правило, следует изменять там. Редактируйте `local_vars.php.inc` только в тех
случаях, когда необходимый параметр недоступен через этот интерфейс.

Расположение файла зависит от установки и проекта. В стандартной установке
Docker он находится в каталоге проекта в веб-приложении OpenBioMaps.

После изменения файла:

1. проверьте синтаксис PHP;
2. перезагрузите затронутую страницу проекта;
3. проверьте журналы приложения и сервера на наличие ошибок; и
4. протестируйте соответствующую функцию с помощью подходящей учётной записи
   пользователя.

Доступные константы могут различаться между выпусками OpenBioMaps. Сохраняйте
настройки, созданные установщиком проекта или Supervisor, если нет конкретной
причины их изменять. Не копируйте полную конфигурацию из другого проекта без
проверки названий проектов, URL-адресов, учётных данных базы данных и
значений, связанных с безопасностью.

Значения в следующих разделах являются примерами. Такие значения, как пароли,
имена хостов, названия проектов, домены и секреты, необходимо заменить
значениями, соответствующими конкретной установке.

## Настройки путей и URL-адресов

| Переменная | Пример значения | Описание |
| --- | --- | --- |
| `PATH` | `/biomaps/resources` | URL-путь, по которому доступны ресурсы проекта. На `openbiomaps.org` обычно используется `/projects`; в другой установке значение может быть пустым или содержать путь, относящийся к конкретному развёртыванию. |
| `URL` | `TYPE-YOUR-SERVER-DOMAIN_HERE` followed by `PATH` | Полный базовый URL-адрес ресурсов проекта. Замените местозаполнитель домена и укажите правильную схему, хост, необязательный порт и путь развёртывания. |

Например, если базовый URL-адрес сервера — `https://example.org`, а `PATH` —
`/biomaps/resources`, результирующим значением `URL` будет
`https://example.org/biomaps/resources`.

## Вход через OpenID Connect

`OPENID_CONNECT` содержит одно или несколько определений поставщиков
идентификации. В примере настроен Google.

| Поставщик/ключ | Пример значения | Описание |
| --- | --- | --- |
| Provider name | `google` | Внутренний идентификатор поставщика OpenID Connect. |
| `client_id` | `xxxxx.apps.googleusercontent.com` | Идентификатор клиента, выданный поставщиком. |
| `client_secret` | `xxxxxxx` | Секрет клиента, выданный поставщиком. Храните его в секрете и не добавляйте в репозиторий. |
| `provider_url` | `https://accounts.google.com/` | Базовый URL-адрес поставщика OpenID Connect. |
| `OPENID_CONNECT_CERT_PATH` | `/etc/ssl/certs/ca-certificates.crt` | Путь к доверенному набору сертификатов центра сертификации, используемому для проверки TLS-соединений с поставщиком. |

Зарегистрируйте у поставщика точный URI перенаправления OpenBioMaps и
убедитесь, что приложение может прочитать настроенный набор сертификатов
центра сертификации.

## Безопасность и проверка автоматизированных запросов

Эти настройки включают проверку частоты запросов на основе Redis. При
превышении установленных ограничений OpenBioMaps может перейти в режим защиты
от атак и отображать проверку «Вы человек?» в течение настроенного времени
действия.

| Переменная | Пример значения | Описание |
| --- | --- | --- |
| `SECURITY_CHECK` | `true` | Включает проверку безопасности. |
| `REDIS_HOST` | `127.0.0.1` | Хост сервера Redis. Задокументированное значение по умолчанию — `127.0.0.1`. В Docker используйте имя сервиса Redis, если Redis работает в другом контейнере. |
| `REDIS_PORT` | `6379` | Порт сервера Redis. Задокументированное значение по умолчанию — `6379`. |
| `SECURITY_IP_LIMIT` | `30` | Максимальное количество запросов с одного IP-адреса за 10 секунд. Установите значение `false`, чтобы отключить проверку по IP-адресу. Задокументированное значение по умолчанию — `30`. |
| `SECURITY_GLOBAL_LIMIT` | `10` | Максимальная общая частота запросов в секунду. Задокументированное значение по умолчанию — `10`. |
| `SECURITY_ATTACK_TTL` | `600` | Время в секундах, в течение которого режим защиты от атак остаётся активным. Задокументированное значение по умолчанию — `600` секунд. |

Выбирайте ограничения с учётом ожидаемого трафика, конфигурации прокси и
количества пользователей, имеющих один видимый исходный IP-адрес. Если
OpenBioMaps работает за обратным прокси, убедитесь, что приложение получает
правильные IP-адреса клиентов.

## Параметры разработчика

Эти параметры предназначены для разработки и устранения неполадок, а не для
обычного использования в рабочей среде.

| Переменная | Пример значения | Описание |
| --- | --- | --- |
| `branch` | `testing` | Выбирает другую ветвь Git, например ветвь тестирования. В рабочих проектах обычно следует использовать поддерживаемую рабочую ветвь. |
| `DEBUG_PDS` | `true` | Включает дополнительное журналирование действий PDS. После устранения неполадок отключите подробное отладочное журналирование, поскольку оно может увеличить объём журналов или раскрыть конфиденциальные эксплуатационные сведения. |

После включения параметра разработчика отслеживайте журналы приложения и
отключите параметр, когда он больше не требуется.
